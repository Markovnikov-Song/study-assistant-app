# 伴学项目蓝图

## 产品定位

伴学是面向学生和长期学习者的学习操作系统。它不是单一聊天机器人，也不是单一刷题工具，而是把“资源 -> 知识结构 -> 学习计划 -> 日历执行 -> 练习/错题/笔记 -> 复盘迭代”串成持续闭环。

## 核心学习闭环

```text
创建科目
  -> 上传或导入课本、讲义、试卷、笔记
  -> 解析资源并建立知识结构
  -> 生成思维导图和讲义
  -> 制定学习计划
  -> 写入日历
  -> 通知提醒
  -> 番茄钟执行
  -> 出题、练习、解题、记笔记、收错题
  -> 复习队列更新掌握度
  -> 调整学习计划
```

## 目标用户

- 初高中、本科、考研、考证等需要长期学习计划的人。
- 有大量教材、讲义、真题、错题需要组织的人。
- 希望 AI 帮忙生成讲义、题目、解题步骤、复习计划的人。
- 容易被手机应用分心，需要日历提醒和专注执行工具的人。

## 设计原则

- 学习任务必须能落到日历和执行层。
- 资源不是文件堆放，必须能进入知识结构和检索来源。
- AI 输出不应只停留在聊天框，应沉淀为讲义、笔记、错题、题目或计划。
- 每个功能都要有可验证状态，不能只有入口。
- 平台权限必须诚实展示，不把系统限制包装成已实现能力。

## 当前状态

多数学习工具已经从“入口占位”推进到可验收的业务流：

- 日历、番茄钟、错题、笔记、出题、练习、解题已有 Playwright 或后端合约覆盖。
- 科目创建、资料库状态和 RAG 来源解析已有自动化覆盖。
- 引导页和示例资源包已有文档化产品闭环。
- 软件工坊仍是主要未完成域，当前有入口和部分运行框架，核心生成、运行、保存、复用闭环仍需继续实现。

## 非目标和限制

- 当前文档不承诺复原每一个内部 helper 函数的实现细节；它记录的是足以重建项目的功能单元、关键类、服务、API 和测试。
- iOS 应用锁、Screen Time 类能力受 Apple entitlement 限制，没有 entitlement 时不能承诺完整实现。
- Playwright 不能替代真机锁屏通知、悬浮窗、后台保活等 L5 平台验收。
